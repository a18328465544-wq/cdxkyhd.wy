# 可搜索硬件选择器设计

## 目标

将装机区域 CPU、GPU、主板、内存、硬盘、电源、散热和机箱的原生下拉框替换为可搜索组合框。用户可按品牌、型号、商品名称、规格和成色筛选 ERP 返回的硬件，并继续使用现有硬件 ID 触发兼容性计算与报价。

## 组件边界

新增复用组件 `SearchablePartSelect`。组件接收当前类目的硬件数组、已选 ID、占位文本和 `onChange`，内部只管理输入文字、展开状态与键盘高亮项，不管理装机业务状态。

`PcBuilderSection` 保留现有八个已选 ID 和回调，将每个类目的库存传给选择器。选择结果仍是硬件 ID，因此后端请求结构不变。

## 搜索与展示

- 搜索忽略大小写及首尾空格。
- 匹配字段包括品牌/商品名称（现有 `name`）、型号文字、`specs` 和 `condition`。
- 选项主行显示商品名称，辅助信息显示成色、价格和库存数量。
- 没有输入时展示该类目全部选项；无匹配时显示“未找到匹配硬件”。
- 选中后输入框展示商品名称；点击清除按钮或“重置所有”后恢复占位文本。

## 交互与无障碍

- 点击输入框或输入文字时展开列表。
- 上下方向键移动高亮项，Enter 选择，Escape 关闭。
- 点击组件外关闭列表；列表高度受限并可滚动。
- 输入框使用 `combobox` 语义，列表使用 `listbox`，选项使用 `option`，并同步展开和选中状态。
- 移动端保持单列全宽，不依赖悬停操作。

## 错误与边界状态

- 配件仍在加载时禁用输入并显示加载提示。
- 空类目显示“暂无可选硬件”。
- 已选硬件不在最新库存中时清空可见名称，但不在组件内擅自修改业务状态。
- 搜索只影响可见选项，不修改 ERP 原始配件数组。

## 测试与验收

- 单元测试覆盖多字段搜索、大小写与空格归一化、空查询和无结果。
- 渲染契约测试确认八个原生 `select` 被可搜索组件替换。
- 浏览器验证输入关键词后选项过滤、键盘选择、清空和重置行为。
- 完整执行测试、TypeScript 检查和生产构建。
